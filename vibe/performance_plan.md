## 现状与原则

- 当前推进双卡 CFG：主卡正分支、辅卡负分支，保持原 float32 CFG 合并与单卡 scheduler；CLI 使用 `--cfg-parallel-device cuda:1`，启动时 `CUDA_VISIBLE_DEVICES=2,3`。关闭所有 Transformer / 文本投影缓存，首版限定 fullgpu、compile 关闭。实现与实测见 [并行报告](../docs/performance.md#parallel)。
- 首轮原尺寸单窗口 40 步：209.788 → 118.259 s（1.774×），去噪 181.240 → 91.399 s；输出逐字节一致。辅卡峰值 allocated 5.631 GiB。仅一次探索测量，≥5 次稳态统计与第二组原尺寸验收待做。

- EraserDiT 已有独立的文本编码、VAE 编码、去噪和 VAE 解码阶段。加载器已有 CPU 加载开关，但此前 EraserDiT 没有阶段搬运，`dynamic_offload` 也没有注册模型。
- `memory/` 的动态卸载、`cache/` 的两个缓存控制器和 `layers/quantization/` 可复用；现有缓存的参数、模型标识和前向接入针对 LTX095，不能直接视为 EraserDiT 已支持。
- 默认保持 `fullgpu`，每种优化显式启用。各项先与无该项的同批基准比较，再测组合。
- 比较固定权重、输入、提示词、seed、窗口参数、dtype、注意力后端和随机性口径。卸载不改变数值计算；缓存和量化另做近似质量验收。

## P1 内存卸载

1. **P1a 整组件阶段卸载（本轮实施）**：新增 `component_offload`。权重从 CPU 加载，文本编码 / VAE 编码 / 完整去噪循环 / VAE 解码进入时搬到执行设备，退出时返回 CPU。整个去噪循环只搬运一次 Transformer，CFG 两路不重复搬运。异常和部分加载失败也执行卸载。
2. 覆盖 CLI、服务启动参数；检查预加载模型路径；未接入的动态卸载明确报错，避免静默在 CPU 上推理。与 Transformer compile 的组合先显式拒绝，单列后续验证。
3. **P1b 按层动态卸载（已接入并通过本轮验证）**：接入 ModelMemoryAdapter 注册与 MemoryPhaseController；核查 EraserDiT block 包装、VAE 根级参数/缓冲区和执行设备；支持权重预算，先验证同步搬运，再加入 pinned memory 与异步预取。激活显存与权重预算分开记录。
4. 验证正常 / 异常 / 连续任务 / 多窗口；记录加载峰值、任务峰值 allocated/reserved、主机 RSS、阶段耗时与搬运时间。不得把 allocator reserved 缓存误判为仍驻留的权重。

P1a 门禁：同参数输出与 fullgpu 对照一致，任务结束模型参数和 buffer 在 CPU；小尺寸 GPU 冒烟通过后，再测两组原尺寸素材。整组件卸载不限制 VAE 激活峰值；VAE 分块是独立质量变更，不能借卸载开关隐式开启。

## P2 TeaCache 与 cache-dit

1. 接入 EraserDiT 请求配置、CLI / 服务参数、模型前向和生效报告；模式互斥：`off | teacache | cache_dit`。
2. TeaCache：复用控制器，核对 timestep embedding 的比较位置、残差位置和系数适用性；LTX095 系数未经 EraserDiT 验证不能作为已校准配置。先保守阈值，再扫阈值。
3. cache-dit：接入前段计算、中段残差复用、尾段计算；校验 block 数与布局、warmup、最大连续复用次数。
4. 正/负 CFG 各自独立缓存；每窗口重建，每任务释放，异常同样清理。覆盖关闭等价、零复用等价、布局变化失效、末步强制计算等边界。
5. 报告完整计算 / 命中步数、实际命中率、缓存显存、去噪和端到端耗时；显式拒绝当前不兼容的整 Transformer compile 组合。

门禁：两组素材完整步骤，分别评估 mask 内、边缘和非擦除区、跨窗口时序；沿用既有近似优化质量线（整帧 SSIM ≥ 0.95、PSNR ≥ 28 dB，另需目视无残留、损坏、时序退化）。阈值未经测量不作为推荐默认值。

## P3 量化

1. 核查实际 GPU 能力、已装内核、EraserDiT 线性层形状；分开报告支持、拒绝与缺依赖。优先评估现有 INT8 路径，FP8 仅在支持硬件上验收。
2. 先 Transformer，再独立评估 T5；VAE 保持原精度。复核输入/输出投影、条件分支及归一化，采用显式层白名单。
3. 验证权重转换、dtype、真实量化 kernel 执行、存储占用与卸载兼容性；不得只以配置非 none 认定量化生效。
4. 单项通过后按顺序测试卸载 + 缓存、卸载 + 量化、缓存 + 量化、三项组合；缓存阈值需重新评估，不能假定质量损失独立。

## 测量与交付

- 两组既有素材：`10268234`（单窗）、`113000356`（双窗）；补充 ≥3 窗与连续任务 / 异常恢复用例。
- 正式性能：每配置至少 5 次，预热独立，记录中位数、离散度、同卡占用和实际生效配置。首次加载/转换/编译独立计时；GPU 异步工作需同步后计时。
- 卸载主要目标为减少显存，允许明确披露的传输耗时；缓存/量化沿用去噪改善 ≥15%、端到端 ≥10% 的推荐配置门槛。达不到则保留可选实验配置。
- 交付配置矩阵、复现命令、结果 JSON、对比视频与推荐配置。没有 GPU 测量或质量验证的项目标为待验收。
