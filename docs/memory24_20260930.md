# 单卡 24 GiB 显存预算

`--vae-low-memory` 限制 VAE 算子中间张量，搭配默认 DiT 逐层卸载、T5 FSDP CPU
offload 和 VAE 组件卸载。CLI 与 HTTP 服务启动入口均支持，默认关闭。

## 运行

```bash
CUDA_VISIBLE_DEVICES=0 HF_HUB_OFFLINE=1 \
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
uv run --no-project python -m entrypoints.cli.erase_eraserdit \
  --model-path data/model \
  --video-input data/113000356.mp4 --mask-input data/113000356_mask.mp4 \
  --output-path outputs/result_24g.mp4 \
  --prompt 'There is a rooftop terrace overlooking the city at sunset.' \
  --attention-backend sdpa --vae-low-memory \
  --dit-layerwise-offload --dit-offload-prefetch-size 0 \
  --text-encoder-cpu-offload --vae-cpu-offload
```

分配器设置用于减少不同窗口/算子尺寸产生的碎片。保留默认 BF16、50 个配置步、
strength=0.8、121 帧窗口与 9 帧重叠；没有开启量化、缓存、编译、VAE tiling 或紧凑尾窗。
不能据此保证任意分辨率或更长窗口都落在同一显存预算内。

## 实现

- RMSNorm 沿时间轴分批，每批保留完整通道归一化维度和原有 FP32 运算顺序，
  避免整块特征同时生成 FP32 转换、平方及乘法张量。
- Conv3d 按输出时间段计算，每段读取卷积需要的全部相邻帧；只有整段视频的首尾
  使用原来的重复填充。空间尺寸、空间填充、权重、感受野和随机数调用顺序不变。
- 空间下采样省去连接空时间前缀所产生的整块复制。

分批阈值为 16 Mi 个输入元素，至少计算一帧。完整输入、输出和残差仍留在 GPU；
这是算子工作区优化，不是独立编码视频分块后拼接。梯度启用时使用原路径。
卷积输入形状会影响 cuDNN 内核选择，BF16 输出不承诺逐像素一致，需整片质量对照。

## 验证方式

本机是 A100 80GB，不能将限额测试表述为 RTX 3090/4090 实卡验证。
在模型加载前调用
`torch.cuda.set_per_process_memory_fraction(22 * 1024**3 / total_memory)`，
把 PyTorch 分配器限制在 22 GiB，为 CUDA 上下文、库工作区等预留空间。
该接口限制的是分配器，不能限制其他进程或所有外部分配，见
[PyTorch 接口说明](https://docs.pytorch.org/docs/stable/generated/torch.cuda.memory.set_per_process_memory_fraction.html)。

在大显存卡上复现限额时，把上面命令的
`python -m entrypoints.cli.erase_eraserdit` 替换为以下入口，保留其余参数，
并在环境变量中增加 `NUMPY_MADVISE_HUGEPAGE=0`：

```bash
python -c 'import torch, runpy; torch.cuda.set_per_process_memory_fraction(22 * 1024**3 / torch.cuda.get_device_properties(0).total_memory); runpy.run_module("entrypoints.cli.erase_eraserdit", run_name="__main__")'
```

使用原始 1920×1080、145 帧、24000/1001 FPS 视频及对应掩码，seed=42，
两个窗口各执行 40 个实际去噪步。基线与候选使用相同完整权重、提示词及采样设置。
Torch 2.6.0+cu126、Diffusers 0.40.0、确定性设置开启。输入对齐到 1088 高供模型处理，
输出保持 1080 高。CPU 历史 peak RSS 约 34.25 GiB；显存卸载仍依赖足够的主机内存。

| 配置 | peak allocated GiB | peak reserved GiB | 完整请求秒数 |
| --- | ---: | ---: | ---: |
| 默认卸载，关闭低显存模式，GPU 3 | 30.653 | 48.387 | 409.72 |
| 低显存模式，22 GiB 限额，GPU 6 | 21.048 | 21.217 | 591.40 |
| 低显存模式，22 GiB 限额，GPU 3 复跑 | 21.048 | 21.217 | 408.91 |

allocated 降低 31.34%。GPU 6 同时存在其他计算任务，上述耗时不能解释为低显存模式的
稳定性能损失。时间包括读取、全部推理和保存，不含模型加载；限额在加载前已生效。
GPU 3 的单次对照耗时接近，不能据此宣称稳定加速。

复跑期间每 50 ms 用 NVML 采样，模型进程显存峰值 **22.059 GiB**，整卡 used 峰值
**22.790 GiB**（包含约 0.685 GiB 初始设备占用）。启动阶段还有一个短暂的 CUDA 算子
测试进程，峰值约 0.480 GiB；整卡值未扣除它。外部采样可能漏掉更短暂峰值，
与贯穿加载和推理的 22 GiB 分配器硬限额共同作为预算验证证据。

完整解码验证两侧均为 145 帧、1920×1080、24000/1001 FPS。RGB 范围 0–255，
SSIM 采用 11×11 Gaussian、sigma=1.5、reflect 边界：

- 整片 SSIM **0.983149**，最低帧 **0.978269**，MSE **2.278913**，MAE **0.990759**。
- 掩码内部 SSIM **0.984630**，掩码边缘 **0.984339**，掩码外部 **0.983119**。
- 帧间误差变化 MAE **1.012506**。抽查 0/24/48/72/96/112/120/132/144 帧，
  两种配置都擦除了人物；仍有纹理和水花细节差异。这不是完整播放验收。

两次低显存运行全部解码的 RGB SHA256 相同：
`7ecfae3e08c379905daf33a3fdde11ca884627cced170d4c9c794593eb98c873`。
基线为 `8fd72becf5fd164de6bc4c6382bb0a84ee7939207c7d4a9796def2853ef0b823`。

**不是无损等价方案，也没有达到整片 SSIM 0.99。** 数学邻域相同不意味着 BF16 卷积、
后续去噪与视频编码的结果完全相同，因此保留显式开关并建议按素材检查输出。

尾段、下采样及输入不被修改、梯度回退和入口参数。CPU 全量 167 项：125 通过、42 跳过；
专项在 CUDA 环境运行 6 项全部通过。命令见 [测试说明](../tests/README.md)。
