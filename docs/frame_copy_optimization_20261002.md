# 帧转换与输出缓存优化（2026-10-02）

在上一轮权重卸载和请求循环引用修复之后，减少整窗帧的临时分配，
并检查每步通信是否值得进一步改造。所有完整推理对照使用同一 121 帧窗口。

## 已实现

- `frames_uint8_to_tensor` / `mask_uint8_to_tensor`：直接创建独立 FP32 存储，再原地除以 255。
  去掉先复制 uint8、再分配 FP32 归一化结果的两次额外分配。
  支持只读、正/负步长 NumPy 视图，不修改或共享调用方输入；数值与输出 strides 保持一致。
- CLI 显式设置 `request_extra={"return_output_tensor": False}`。
  preload 保存视频时直接使用帧缓存，不再为 CLI 创建额外的整窗 FP32 返回视频。
  `EraseSession` 默认返回行为保持不变；未保存文件时仍返回张量。
  对 streaming 保存路径不改变原有返回行为。
- 预热指标汇总完成后释放预热请求和结果，避免正式推理时仍保留预热视频。

这是帧存储优化，不改变权重、精度、采样、去噪步数或 VAE 卸载模式。
此前的 VAE `cached` 仍是可选路径，本轮对照固定使用 `full`。

## 单窗口转换内存测量

每种情况在独立进程运行原始表达式或优化后的函数，输入为 121×1080×1920、uint8，
8 个 CPU 线程，关闭 NumPy hugepage hint。报告 `ru_maxrss` 减去输入分配前进程峰值；
包含输入与输出，不是整条推理的内存峰值，也不包含模型。

| 转换 | 原版增量峰值 RSS / GiB | 优化版 / GiB | 减少 |
| --- | ---: | ---: | ---: |
| RGB 视频 | 6.305 | 3.506 | 2.799 GiB |
| 单通道掩码 | 2.102 | 1.170 | 0.932 GiB |

原版与新版输出均为 FP32、相同布局；测试覆盖 uint8 全部取值、FP32 输入、非连续/反向/只读视图和存储独立性。
转换耗时不计作纯模型推理加速，本文不把它加入纯推理耗时。
仅文件输出另外避免构造一份约 2.804 GiB 的 FP32 返回视频；实际进程收益由完整对照验证。

## 每步 CPU 中转检查

检查前轮相同 CFG2×SP2、40 有效去噪步、121 帧日志：

- 父进程输入 GPU→CPU 累计约 0.094–0.096 秒；输出 CPU→GPU 约 0.179–0.207 秒。
- 每窗逻辑输入 370,015,648 字节，输出 668,467,200 字节；这不是 PCIe 硬件传输计数。
- worker 往返约 69.4–69.8 秒，其中包含模型计算，不能全部当作 IPC 开销。
  rank 0 的广播 GPU 计时约 0.22–0.24 秒、forward/汇聚约 68.2–68.6 秒。
  不同边界计时口径有同步和重叠，不能简单相减得到精确 IPC 时间。

当前明确可见的父进程搬运约 0.28–0.30 秒，仅占约 84 秒纯推理的 0.3–0.4%；
**这不是所有 IPC 成本**。现有证据不支持本轮立即把 scheduler 迁入 worker。
保留边界计时，之后需要 profiler 分解同步等待、序列化及 worker 拷贝后再决定。

SP 注意力的跨卡交换不能直接删除。现有 `MGERASE_NCCL_PACKING=packed` 已减少逐片打包副本，
见[单窗口并行优化](window_optimization_20261002.md)。跨调用复用收发缓冲涉及异步通信生命周期和形状切换，
本轮不引入未经实测的缓冲池，也不把重复分配次数直接当作性能瓶颈。

## 完整对照

同一卡组 0–3，CFG2×SP2，BF16 SDPA、DiT 常驻、T5/VAE 卸载、VAE low-memory，
reference Ulysses packing；相同素材、seed、50 配置步数、strength=0.8（40 有效步）。
加载和预热不计入纯推理，基线和优化版各 3 次常驻请求。
基线使用本轮修改前源码，保留上一轮的请求引用释放修复。

| 指标 | 基线（3 次） | 优化版（3 次） |
| --- | ---: | ---: |
| 纯推理中位数 / 秒 | 87.731 | 85.022 |
| 纯推理范围 / 秒 | 86.344–87.748 | 84.592–85.253 |
| 去噪中位数 / 秒 | 74.106 | 71.433 |
| owner 阶段末 RSS / GiB | 33.406–33.406 | 30.642–30.642 |
| owner 峰值 allocated / GiB | 20.842 | 20.842 |

确定收益：相同阶段采样点 CPU RSS 减少约 **2.764 GiB（8.3%）**，
连续 3 次稳定；该数字不是整个请求的 RSS 峰值或全部 worker 内存总和。
GPU allocated 不变，本轮没有改变模型或 GPU 激活策略。

纯推理中位数观察到下降约 3.1%，但 2.709 秒差异中去噪阶段约占 2.672 秒，
而帧转换/输出构造主要位于纯模型计时之外。因此不能将此差异归因于消除帧复制，
不承诺固定比例的纯推理加速。采用相同卡组顺序测量，未进行随机交替实验。
