# 同四卡 DP 吞吐与延迟筛选

8×L40S 机器，使用 GPU 0–3；卡间均为 PHB、无 NVLink，CPU NUMA0。
相同 121 帧 1080p 固定输入、两条独立同 seed 任务。常驻 NCCL、CFG2、sharded Linear、
BF16/SDPA、40 实际步，启用融合/direct 打包、VAE 激活优化和后处理分块；缓存、编译、量化关闭。
每 worker 加载一次并进行 2 步预热；任务不拆分跨窗依赖。源码冻结于
`outputs/vae_stream_acceptance_20261002/source/`，完整参数在本实验 `runs.json`。

| 指标 | DP1×CFG2×SP2：四卡依次处理两条 | DP2×CFG2×SP1：两组双卡同时处理 |
| --- | ---: | ---: |
| 两条任务墙钟，含加载/预热/退出 | 306.880 s | 243.392 s |
| 上述冷批次吞吐 | 0.391 条/min | 0.493 条/min |
| 单条正式端到端延迟 | 98.387 / 100.052 s | 128.094 / 131.430 s |
| 单条纯推理 | 77.942 / 79.116 s | 105.836 / 109.676 s |
| 按正式耗时估算的服务率 | 0.605 条/min | 0.913 条/min |
| 进程树采样 USS 峰值 | 32.684 GiB | 60.236 GiB |
| 各 GPU 采样 memory.used 峰值 | 44.355 / 12.290 / 12.294 / 12.251 GiB | 44.270 / 7.872 / 44.270 / 7.872 GiB |

本次 DP2 将冷批次墙钟降低 20.69%，吞吐增加 26.08%，单条平均延迟增加 30.78%。
正式服务率按 `任务数 / max(各 worker 正式耗时之和)` 估算，DP2 高 50.99%；它扣除了加载与
预热，不是实际冷批次吞吐，也不是长时间持续到达请求的测量。两组各仅一个批次，属于配置筛选，
不能替代五组配对或容量测试。没有足够请求或 CPU 内存时不应直接增大 DP。

USS 统计本实验所有 owner/worker/子进程的私有页，避免累加 RSS 重复计算共享页。
采样名义间隔 5 秒，读取进程内存也有成本，可能漏过瞬时峰值，且第一组采样略晚于启动。
GPU memory.used 包含 allocator 保留池、worker 与 CUDA/NCCL 上下文，不等于 owner 的
19.21 GiB 峰值 allocated；部署时需按整卡占用评估。第二组 CPU 权重及帧缓存副本解释了
更高私有内存，但该实验没有单独归因每项内存。

两种配置内的重复任务分别逐字节一致。CFG2×SP2 与前述精确参考哈希一致；跨 SP 配置改变
计算形状，输出不逐字节一致，不将换拓扑列为精确优化。跨拓扑完整视频指标见下文。

原始命令、worker 日志、采样、汇总及视频：`outputs/dp_topology_screen_20261002/`。
`run.py` 执行真实 dispatcher，`summarize.py` 解析正式与冷启动时间，`quality.py` 比较跨拓扑视频。
