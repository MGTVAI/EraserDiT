# L40S FP16 / FP8 / INT8 对照（2026-10-03）

在原 FP16/FP8 benchmark 中增加 INT8，三种模式在同一轮重新测量；不拼接之前不同轮的数据。
单张空闲 L40S GPU 0，PyTorch 2.6.0+cu126，真实第 0 层权重和固定 seed 的 FP16 正态随机激活。
预热后五组，每组二十次，交替正反顺序。下表为 CUDA Graph 中位数，单位 ms。
FP16 reduced-precision reduction 使用 PyTorch 默认开启；FP8 E4M3，use_fast_accum=False。

## 预量化 GEMM

FP16 和 FP8 输出均为 FP16，FP8 标量缩放在 GEMM 内完成；不包含输入量化和 bias。
INT8 原生 GEMM 输出 INT32，不能直接当作与其他列完全等价的操作；同时列出包含行/通道缩放、
FP16 回写的耗时。INT8 权重按通道、激活按 token 预量化。默认两个 M 无需行数 padding。

| M×K×N | FP16 | FP8→FP16 | INT8→INT32 原生 | INT8 缩放回写 FP16 |
| --- | ---: | ---: | ---: | ---: |
| 1200×2048×2048 | 0.075 | 0.038 | 0.043 | 0.048 |
| 32640×2048×2048 | 1.362 | 0.763 | 0.806 | 1.355 |
| 1200×2048×8192 | 0.235 | 0.119 | 0.135 | 0.151 |
| 32640×2048×8192 | 5.984 | 3.382 | 3.242 | 5.146 |
| 1200×8192×2048 | 0.194 | 0.161 | 0.171 | 0.176 |
| 32640×8192×2048 | 5.953 | 3.183 | 2.981 | 3.183 |

## 完整 Linear

输入和输出均为 FP16，包含动态激活量化、GEMM、缩放和 bias。INT8 在 M≥1024、N≥2K 时使用
与生产实现相同的融合 GEMM，仅在 benchmark 内将输出设为 FP16；其余使用原生 INT8 GEMM+epilogue。
FP8 保持当前分离 FP32 中间结果路径。权重量化为一次性准备，不计入稳态调用。

大 FFN 扩展层中，INT8 融合路径 3.542 ms，对比 FP16 5.539 ms 为约 1.56×，
对比当前 FP8 6.217 ms 为约 1.76×。这些收益包含融合实现的差异，不是对两种 8-bit 格式硬件峰值的比较。
完整融合 Linear 比分离的预量化 INT8 路径快，是因为避免了 INT32 大矩阵写回和再次读取。

## 数值与范围

所有输出均有限；FP16 适配后的融合 INT8 输出与原生 INT8 GEMM+epilogue 逐元素一致，
该断言在所有启用融合的测试形状上通过。INT8 Linear 相对 FP16 的 relative RMSE 为 1.48%–1.73%，
FP8 约 3.7%；这是合成激活上的算子误差，不代表视频质量。未改变生产推理 dtype，未重跑视频验收。
CUDA Graph 与普通调用分别报告；原始 JSON 保留每组样本及 min/max，较大 FP16/INT8 GEMM 存在波动。

## 复现

```bash
CUDA_VISIBLE_DEVICES=0 uv run --no-project python \
  -m entrypoints.cli.benchmark_fp16_fp8 \
  --output results/fp16_fp8_int8_new/measure.json
```

保留入口名以兼容原命令；现在默认包含三种精度。
原始数据和日志在 `results/fp16_fp8_int8_20261003/`。
