# 单卡下一阶段优化方案（2026-09-27）

> 此文保留阶段方案；当前支持范围见[性能配置](performance.md)，后续实施见[记录索引](README.md#实验与验证记录)。

先在当前低显存、融合开启的路径上继续优化去噪；残差缓存作为独立的可选有损路线。
仅参考本地 SGLang 实现，不将其作为包引入。不通过减少步数、缩小输入或增加 GPU 报告提速。
本文是下一阶段实施方案，尚未实施的项目不代表已经获得收益。

阶段 1–3 的实施与筛选结果见 [验证记录](single_gpu_optimization_20260927.md)：
新增残差融合保持显式启用；FFN 编译因收益不足暂停卸载适配，阶段 4 尚未实施。

后续用户允许近似计算后，已接入阶段 4 的 TeaCache 卸载计划，并增加尾窗口减填充实验。
实现与原始结果见 [0.99 质量目标验证](quality99_optimization_20260927.md)。
用户随后将整段门槛调整为 [RGB SSIM ≥ 0.985](quality985_optimization_20260927.md)，优先验证新版 SageAttention。
最新门槛为 [RGB SSIM ≥ 0.98](quality98_optimization_20260927.md)，已适配单卡卸载下的 FFN 编译预热及图外融合。
下文关于禁止 compile + offload 的描述保留为原方案背景，当前支持范围以上述最新记录为准。

## 当前基线与瓶颈

基线来自 [融合验证报告](performance_optimization_20260927.md)：单张 A100 80GB，
1920×1080、145 帧，窗口 121、重叠 9，seed=42，配置 50 步、strength=0.8，
每窗口实际去噪 40 步；BF16、SDPA、逐层卸载、T5/VAE CPU offload，
`--operator-fusion-backend auto`，文本投影和残差缓存关闭。

| 指标 | 已测结果 | 对下一步的影响 |
|---|---:|---|
| 完整请求 | 391.85 s | 单次观测，尚非完整请求交替重复统计 |
| 去噪 | 340.45 s，约 86.9% | 优先减少 DiT 计算与张量读写 |
| VAE 编码 / 解码 | 13.83 / 6.35 s | 对耗时贡献较小，但编码决定显存峰值 |
| GPU peak allocated / reserved | 30.653 / 48.387 GiB | 两者分开报告，不把 reserved 当作活跃张量大小 |
| 融合后 DiT forward 中位数 | 全驻留 2099.67 ms；逐层 2106.91 ms | 大输入未显示明显卸载劣势；两组顺序执行，不能精确归因 |

融合前真实形状 resident trace 中，self-attention 占 CUDA kernel 时间约 57%，
GEMM 约 18%。这些不是融合后的占比，需要重新采样。现有 SDPA 已走 FlashAttention kernel；
独立后端探测的外部 FlashAttention / SageAttention 收益很小且存在数值差异，暂不替换默认。

当前融合输出与上一轮显存优化后的基线逐像素一致。显存优化相对更早原始实现的差异仍在，
整段 RGB SSIM 约 0.99633；不能将现状表述为相对原始实现完全无损。
后续同时保留“当前基线”和“原始基线”两个质量对照，避免多轮差异累积被掩盖。

## 实施顺序

### 1. 固定基线，筛选现有文本投影缓存

先对融合后的路径采样，区分 attention、GEMM、逐元素操作、H2D 和 CPU 等待。
记录阶段耗时、GPU allocated/reserved、进程 RSS，以及请求结束后的受管权重驻留量。
完整请求采用同一空闲 GPU、两条路径分别预热、五组交替 A/B 测量；加载、编译、冷启动单列。
同时保留小尺寸和中尺寸输入，避免将 1080p 的计算瓶颈外推到所有请求。

第一个候选只在现有基线上增加 `--cache-text-projections`，残差模式仍为 `off`。
当前代码已经支持此组合：它复用每个 CFG 分支的文本投影及 cross-attention K/V，
与已经实现的 T5 prompt 缓存不同，无需先改卸载调度器。
检查窗口内命中率、实际保存字节、窗口结束释放、条件变更失效和视频逐像素一致性。
这是成本较低的实验，不预先承诺明显收益；文本序列较短，收益可能有限。

### 2. 根据新 trace 扩展精确逐元素融合

优先检查 residual gate + add 等仍产生完整 token 张量的操作；仅在 profile 显示足够成本时实现。
沿用本轮成功的数值边界：保留原生归约、GEMM 和必要的 BF16 中间舍入，
融合张量读取与逐元素计算。不能把代数等价当作 BF16 输出一致。

每个候选先做真实形状 microbenchmark、极值输入及完整 block 对比，再跑完整视频。
覆盖短尾窗口、非连续布局的回退、两次连续请求，以及逐层预取与释放。
显存不增加是默认约束；若需要持久缓冲，必须报告大小和释放边界。

### 3. 有条件推进局部 FFN compile

先证明 resident FFN 编译在真实形状下有收益，再处理与逐层卸载的组合。
当前 `memory/validation.py` 禁止 offload + compile，融合 registry 也会在 compile 开启时关闭融合。
因此不能仅删除配置校验后宣称支持。

实现范围限定为纯 FFN 计算：搬运、CUDA event 和 Module hooks 留在图外，初期关闭 CUDA graphs；
保留已有 native linear 的舍入边界。预热改为只在对应 block 权重已加载时执行，
避免现有全 block 预热逻辑要求权重同时驻留。验证权重 `.data` 切换不会捕获占位 storage、
产生陈旧引用或持续重编译，再允许 FFN compile 与图外的精确融合共存。

验收除性能和质量外，必须包含 shape 切换、重复加载/释放、编译次数及异常后的清理。
若 FFN 微基准无稳定收益，停止此分支，不为接通配置组合投入大规模改造。

### 4. 单独推进残差缓存与卸载协同

需要更大幅度提速时，评估跳过部分 DiT 计算的 TeaCache；CacheDiT 后续再接。
这是可能改变输出的独立选项，不默认开启，也不复用迁移前测得的加速比作为当前承诺。

当前循环逐层预取假设顺序执行所有 block，与跳步存在冲突，代码明确禁止组合。
参考 SGLang 的计算边界和调度方式，建立“本步实际执行哪些 block”的卸载计划：
完整计算、探针计算、缓存命中分别处理；取消无用预取，确保 event 完成前 storage 不被释放。
CFG 正负分支独立缓存，窗口边界重置，并明确缓存激活的显存预算。

测试命中/未命中交替、首尾步保护、跨窗口、请求取消和异常恢复；报告实际计算步数、
复用率、H2D 字节及峰值显存。以多个运动强度、遮罩面积和场景的素材验收，
既报告整段指标，也检查逐帧最低值、尾窗口和时间闪烁；达到既定质量要求前保持实验选项。

## 显存路线保留，但与耗时收益分开

继续降低 DiT 权重驻留不能解决当前 VAE 编码峰值。若目标变为 24 GiB 单卡，
应优先研究 VAE 激活分块与生命周期，而不是继续增大卸载力度。
可参考 SGLang LTX VAE 的 temporal/spatial tiling、halo 和重叠融合，但必须针对当前 VAE
验证因果边界、归一化、posterior 采样及拼接结果；不同模型不能直接继承质量结论。
之前小 tile 配置质量未达标，不能直接作为默认方案。CPU offload 也会增加主机内存压力，
GPU 与 CPU 的内存指标必须一起跟踪。

暂不优先：扩大预取深度、完整 CUDA graph、B2 合并 CFG、替换 attention 后端。
前两者需先证明传输或 launch 开销是瓶颈；合并 CFG 增加激活且改变 GEMM 形状，
现有 AdaLN 融合也有限定 batch 的契约，不能预期简单获得两倍速度。

## 验收与收益目标

- 精确路线：完整解码后的 RGB 相对当前基线逐像素一致；GPU 峰值不出现超过测量波动的回退；
  请求结束后缓存和权重按策略释放。若存在差异，明确转为有损候选，不能沿用精确标签。
- 性能路线：报告五组配对请求的中位数、离散程度和逐组差异。建议将稳定的端到端收益达到 3%
  作为复杂实现的合入目标；收益小于运行噪声的候选不纳入默认配置。
- 缓存路线：质量与提速共同验收，独立报告额外显存，不与精确融合的收益直接相乘。
- 回归范围：相关算子精度、卸载生命周期、缓存失效及现有 CPU/GPU 专项；每项优化单独对照，
  最后再测试组合，保留一键关闭优化的参考路径。

以单次 391.85 s 为估算起点，其他阶段不变时，去噪耗时减少 10% 约对应请求减少 8.7%。
达到 350 s 需要去噪减少约 12.3%；达到 300 s 需要约 27.0%。这是工作量目标的算术换算，
不是已经测得或保证达到的收益。先完成阶段 1 和 2，再依据 profile 决定编译的投入；
更激进的目标由阶段 4 单独评估。
