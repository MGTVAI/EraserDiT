# 双卡完整视频验证（2026-09-30）

当前 EraserDiT 的 LTX VAE 空间并行在完整视频上跑通，两种配置各完成三次。
主卡 allocated 峰值从 **42.96 降至 32.36 GiB（降低 24.7%）**。
但候选相对对照的整片 SSIM 为 **0.98313**，未达到本轮预设的 **0.99** 一致性门槛。
运行完整、同配置可复现，不等于跨配置数值一致性通过。

本轮只增加实验脚本和记录，推理 Python 源码运行前后 SHA256 一致；没有修改算法或目录结构。
独立 VAE 的前一轮结果见 [VAE 空间并行验证](vae_spatial_validation_20260929.md)。

## 对照条件与测量

- 两张 A100 80GB / NVLink，物理 GPU 6、7；Python 3.10，Torch 2.6.0+cu126。
- 输入 `data/113000356.mp4` 和对应 mask，1920×1080、145 帧、24000/1001 fps。
- Prompt：`There is a rooftop terrace overlooking the city at sunset.`，seed 42。
- BF16、SDPA、CFG2/SP1、50 配置步、strength 0.8、guidance 3；两个窗口各 40 个实际去噪步骤。
- infer_len 121、overlap 9、完整尾窗；关闭 tiling、紧凑尾窗、编译、手工融合、量化和缓存。
- T5、DiT、VAE 常驻；两组只改变 `vae_degree=1/2`，两组 DiT 均使用双卡 CFG。
- 正式 CLI 参数解析和 `EraseSession`，同一常驻会话，完成顺序为 2/1、1/2、2/1。

模型加载 **43.74 秒**单列。请求时间包含视频读取、预处理、模型执行、后处理与输出保存。
阶段边界同步两卡；按阶段重置并累计各区间（包括阶段之间）的峰值，不额外清空 allocator 缓存。
allocated 和 reserved 分开报告，不把两卡各自峰值之和当成同时总峰值。
GPU 进程、显存、利用率每两秒采样；manifest 保存输入和受 Git 跟踪的 Python 源码 SHA256。

每个双卡 VAE 请求都验证两个窗口的编码、解码阶段：`algorithm=spatial_halo`、
`effective_degree=2`，每卡编码 46 次卷积、解码 45 次卷积；CFG 阶段每窗执行 40 步。
日志的 `native_vae_parallel=False` 属于另一套原生并行字段，不代表 adapter 未执行。

## 显存峰值

以下是本进程 PyTorch allocated，单位 GiB；每种配置三次完整请求的峰值相同。
卡 0/1 分别对应物理 GPU 6/7，统计包括组件常驻权重与流水线上下文。

| 阶段 | VAE1 卡 0 | VAE1 卡 1 | VAE2 卡 0 | VAE2 卡 1 |
| --- | ---: | ---: | ---: | ---: |
| 整个请求 | 42.96 | 5.82 | 32.36 | 20.92 |
| 预处理（暖态） | 32.22 | 3.68 | 32.22 | 3.68 |
| VAE 编码 | 42.96 | 3.68 | 32.36 | 20.92 |
| DiT 去噪 | 17.09 | 5.82 | 17.09 | 5.82 |
| VAE 解码 | 38.67 | 3.68 | 28.77 | 18.55 |
| 窗口后处理 | 22.67 | 3.68 | 22.67 | 3.68 |

主卡峰值减少 **10.60 GiB / 24.68%**，代价是副卡峰值增加约 **15.10 GiB**。
这减少了单卡容量压力，并不表示两卡总占用减少。
预处理的 32.22 GiB 已接近并行编码的 32.36 GiB；继续降主卡峰值需要同时优化预处理和完整输入驻留。

相邻暖态请求的 reserved 峰值分别为 **52.44 / 6.36 GiB** 与 **51.93 / 23.08 GiB**。
同一会话交替配置，allocator 会保留前一个请求的缓存；不能用 reserved 的变化代表张量内存收益。
每两秒 NVML 采样中，本进程两卡占用最大约 **53.03 / 23.67 GiB**，包含缓存和 CUDA 上下文，
属于整个混合会话的采样值，不能分配给某一种配置，也不能作为无采样遗漏的瞬时峰值。
设备总占用还包含其他任务，不能据此归因当前模型。

## 正确性与画质

六个输出均通过 ffprobe 的帧数、分辨率、帧率检查和 FFmpeg `-xerror` 完整解码。
每种配置三次的文件 SHA256、解码 RGB SHA256 均完全一致。两种配置之间不一致：

| 完整视频比较 | 结果 |
| --- | ---: |
| 平均 SSIM | 0.983133 |
| 最低帧 SSIM | 0.978295（第 144 帧，从 0 开始） |
| SSIM < 0.99 的帧 | 144 / 145 |
| mask 内平均 SSIM | 0.984491 |
| mask 边缘平均 SSIM | 0.984311 |
| mask 外平均 SSIM | 0.983108 |
| 高度分片接缝带平均 SSIM | 0.984214 |
| 窗口边界附近平均 SSIM | 0.981129 |
| 像素 MAE / MSE（0–255） | 0.990512 / 2.280436 |

在解码后的完整分辨率三通道像素上计算 SSIM，Gaussian 11×11、sigma 1.5、reflect 边界；
先计算逐帧指标再平均。mask 阈值为任一通道 >10，边缘为 17×17 膨胀减腐蚀，空区域不计入区域均值。
接缝带为行 `[516:564]`，窗口边界统计帧 `[108:125]`。这些是编码后视频的比较，没有缩放输入指标图像。

人工查看了全部 145 帧的缩小 mask 区域对照图，以及 8 帧整图概览。
在该查看尺度下，两种配置均未见明显人物残留、黑块或水平分片接缝，背景和水纹存在细微差异。
mask 最后非空帧为 102；之后区域图沿用最后的裁剪框。这不是原分辨率实时播放验收，
也不能覆盖平均 SSIM 未达到 0.99 的结论。

前一轮固定 latent 的独立 decoder SSIM 0.999774，不能代替本轮 encode → DiT → decode 结果。
编码舍入差异经去噪和窗口反馈放大是待验证的解释，本轮没有通过分离 encode/decode 的消融定位根因。
下一步应先定位跨配置数值差异，再优化预处理峰值；不能把当前候选标为 0.99 质量通过。

## 资源干扰与停止原因

最初在 GPU 3、6 试跑，GPU 3 外部任务占用增长，首请求在预处理 OOM。
对应 `results/vae_e2e_20260930_interrupted_3_6*` 单独保留，不进入上述结果。

最终 GPU 7 已有两个外部驻留进程，合计约 12.80 GiB。
GPU 6 在 `vae2_0` 中出现临时 PID 1618141（采样峰值 44508 MiB，01:14:04–01:15:34 UTC）；
在 `vae2_2` 中又出现 PID 1748586（14072 MiB），并使最后一轮去噪接近翻倍。
原计划每种配置五次，因此改为各完成三次后停止其余重复，保留所有原始测量。
只向本次 benchmark 发送 SIGINT；第七个请求 `vae1_3` 在读视频时中断，无模型阶段执行，已排除。
原始 report 的 `KeyboardInterrupt` 对应这次主动停止，前六个请求均完整保存。

## 复现与产物

实验脚本、全部参数、资源采样、原始阶段记录位于现有的 `results/`，该目录被 Git 忽略，不随仓库分发。

```bash
CUDA_VISIBLE_DEVICES=6,7 PYTHONPATH=. HF_HUB_OFFLINE=1 OMP_NUM_THREADS=4 \
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
uv run --no-project --python /mnt/shanhai-ai/envs/conda/envs/EraserDiT/bin/python \
  python results/vae_e2e_20260930.py
```

前缀 `results/vae_e2e_20260930`：

- `.py` / `.log`：实验脚本与执行日志。
