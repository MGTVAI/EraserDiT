# L40S 性能复测方案

后续复测以 [README 当前约定](../README.md#性能数据与复测结果)为准：逐阶段继承上一阶段
实测最快的完整配置，再叠加本阶段候选；按 GPU 数分别选优，缓存胜出配置继续带入量化阶段。
候选变慢时保留上一阶段最佳配置；不兼容组合先补齐支持，不静默关闭已有优化。
完整请求耗时用于选优，质量独立记录；保存继承来源、完整参数与实际生效配置。
下文的固定 S3/CFG 配置、无缓存量化矩阵、旧样本复用、重复次数及执行顺序是历史方案，
不覆盖上述累积复测要求。

本方案只定义复测范围和验收方法，不启动测试。目标是补齐原始算法与当前单卡路径之间的
可比较数据，并为每个既定测试补齐请求与模型各阶段的完整性能记录。
本方案的所有配置都不设质量门禁；质量只记录，不决定性能测试的启动、继续或数据保留。

## 1. 要回答的问题

1. 原始 `alg` 路径在 CPU offload + VAE tiling 后，排除加载和预热的稳态整片耗时是多少？
2. 当前单卡路径中，`windowed_preload` → 窗口流式、逐层卸载 → 组件卸载、精确融合各自带来多少收益？
3. 已验收的 1/2/4 卡结果哪些可以直接复用，VAE、缓存和量化候选在同一口径下的性能如何？

不用本轮数据声称跨 GPU 型号、跨视频或跨依赖版本的普遍加速。

## 2. 先固定测量口径

| 项目 | 固定值 |
| --- | --- |
| 硬件 | 同一台 NVIDIA L40S；正式测试使用无外部计算进程的物理卡 |
| 输入 | `data/113000356.mp4` / `data/113000356_mask.mp4`，记录完整 SHA-256 |
| 视频 | 1920×1080、145 帧、24000/1001 fps；模型内部高度 1088 |
| 窗口 | `infer_len=121`、`overlap=9`、关闭 compact tail padding，共两窗 |
| 采样 | prompt `There is a bridge over the lake.`；seed 42；CFG 3；50 步、strength 0.8，每窗 40 个去噪步 |
| 公共基准数值 | BF16 + SDPA；缓存、量化、compile、快速近似融合关闭；候选矩阵仅改变当行明确列出的因素 |
| 预热 | 每个会话显式预热 2 步；预热时间单列 |
| 重复 | 每配置在同一预热会话内连续完成 5 个正式请求；加载和预热时间单列，不进入请求统计 |
| 请求边界 | 从视频读取到输出写完；排除模型加载和显式预热 |
| 显存 | 0.1 s NVML 采样；按同卡本任务全进程树占用之和取峰值；同时保存 allocated/reserved |
| 性能隔离 | 正式运行期间不并行质量分析、回归测试或其他 GPU 实验 |

请求、纯模型推理、文本编码、VAE 编码、DiT 去噪、VAE 解码、通用预/后处理和输出写入
必须分列。各列独立取中位数，不要用四舍五入后的分项反推总时间。

## 3. 源码与依赖冻结

- B0 使用原始全驻留提交 `410038e`；B1 使用只增加阶段卸载的 `alg` 提交
  `6a658482d0caf68dfd26fd4fe6da71b1d652b7e4`。除了将 seed 显式固定为 42，不修改算法源码。
- B0/B1 使用原始路径已验证的 Diffusers 0.33.1、Transformers 4.51.3 依赖集；当前路径使用仓库锁定环境。
- S0–S3 必须来自同一份冻结源码快照，只通过 CLI/环境开关改变待测因素。
- 原始与当前路径的依赖、预处理和 VAE tiling 不同，因此 B1 → S0 只报告“跨实现工程加速”；
  只有 S0–S3 可解释为同源码开关消融。

每次运行保存 Git HEAD、工作区 diff、冻结源码 SHA-256、Python 包版本、`nvidia-smi`、GPU 拓扑、
输入和模型指纹。源码在运行期间发生变化时，整个批次作废。

## 4. 必须复测的单卡矩阵

| ID | 只改变的因素 | 关键配置 | 重复 | 用途 |
| --- | --- | --- | ---: | --- |
| B0 | 原始算法全驻留 | BF16/SDPA，不卸载、不 tiling | 1 次，直到成功或 OOM | 确认失败阶段与峰值，不计算加速比 |
| B1 | 原始算法可运行基线 | `cpu_offload=true`、`vae_tiling=true` | 5 | 作为跨实现工程基线 |
| S0 | 当前架构基线 | `runtime_mode=windowed_preload`、DiT 逐层卸载、VAE low-memory、融合关闭 | 5 | 当前同源码消融起点 |
| S1 | 流式窗口 | S0 + `runtime_mode=windowed_streaming` + `streaming_cache_dtype=uint8` | 5 | 隔离流式 I/O/帧缓存的整片和 CPU 内存影响 |
| S2 | 卸载策略 | S1 + 关闭逐层卸载 + 开启 DiT 组件卸载 | 5 | 隔离权重传输和调度差异 |
| S3 | 精确融合 | S2 + `qk_rmsnorm_rope,rmsnorm_adaln` | 已有 5 | 当前单卡最终配置 |

内存生命周期中没有开关的代码改动不单独声称加速比。若确实需要量化这些改动，应在两个明确提交快照间
增加第二组跨提交对照，不得把它混入 S0–S3 开关消融。

## 5. 复用的已有结果

以下结果已使用同一输入和参数、各 1 个会话×5 次正式请求，并完成输出一致性、进程树显存和源码冻结核验：

- S3 / M0：单卡 BF16 组件卸载与精确融合。
- M1：双卡 NCCL CFG2。
- M3：四卡 CFG2×SP2 `reference`。
- M4：M3 + Ulysses 输出通信重叠/head 分块 4。
- 批量：DP2、DP4、CFG2×DP2。

S3/M1/M3/M4 的 5 次正式请求直接计入统一总表，不增加素材或 seed。仅新增 M2：双卡
SP2 `reference` 的 5 次请求；原 M2/M3 顺延为 M3/M4。

## 6. 不设质量门禁的候选性能矩阵

所有下列配置都进入性能测试，不会因历史或本轮质量分数而停止。质量指标独立记录，
只用于说明输出差异和适用范围，不用于决定是否执行后续性能配置。

### 6.1 VAE 与 DiT 并行组合

VAE degree 只能是 1 或等于当前 DiT world size，因此正式矩阵为：

| ID | GPU | DiT | VAE | 重复 | 备注 |
| --- | ---: | --- | ---: | ---: | --- |
| V0 | 2 | CFG2 | 1 | 5 | 双卡 VAE 对照 |
| V1 | 2 | CFG2 | 2 | 5 | 双卡 VAE 空间并行 |
| V2 | 2 | SP2 `reference` | 1 | 5 | 分离 DiT 拓扑影响 |
| V3 | 2 | SP2 `reference` | 2 | 5 | SP2 + VAE2 |
| V4 | 4 | CFG2×SP2 `reference` | 1 | 5 | 四卡 VAE 对照 |
| V5 | 4 | CFG2×SP2 `reference` | 4 | 5 | CFG2×SP2 + VAE4 |

六组均禁用 VAE tiling、VAE 组件卸载和 VAE compile，统一开启 `vae_low_memory`，其他参数固定。
显存超过 24 GiB 仍保留有效耗时结果，单独标记未达内存目标，不因此跳过后续组合。除整片耗时外，单列 VAE encode/decode、
DiT、每卡 allocated/reserved/NVML 峰值和并行历史。固定 latent/后验样本的 encode/decode 误差分析可同时进行，
但不作为 V0–V5 的执行前置条件。

### 6.2 TeaCache / CacheDiT

缓存组统一使用 S3 的 BF16/SDPA、精确融合和单卡组件卸载路径，完整处理 145 帧：

| ID | 配置 | 重复 |
| --- | --- | ---: |
| C0 | Cache off，与 S3 同一配置 | 共用 S3 已有 5 次 |
| C1 | TeaCache 0.01，最多连续复用 1 步 | 5 |
| C2 | TeaCache 0.1，最多连续复用 1 步 | 5 |
| C3 | TeaCache 0.3，最多连续复用 1 步 | 5 |
| C4 | CacheDiT 0.02，前 1 / 后 0，最多连续复用 1 步 | 5 |
| C5 | CacheDiT 0.1，前 1 / 后 0，最多连续复用 1 步 | 5 |
| C6 | CacheDiT 0.3，前 1 / 后 0，最多连续复用 1 步 | 5 |

报告每窗正/负 CFG 分支的实算步、复用步、探针调用、尾部保护步和额外缓存内存。

### 6.3 INT8 / FP8 / Sage / 近似融合

量化与近似路径统一使用单卡、145 帧完整素材和组件卸载；不与 NCCL、缓存或 compile 叠加：

| ID | 配置 | 重复 |
| --- | --- | ---: |
| Q0 | BF16 FFN + SDPA + 精确 QK/AdaLN 融合 | 与 S3 共用已有 5 次 |
| Q1 | INT8 FFN，其他同 Q0 | 5 |
| Q2 | 动态 FP8 FFN，其他同 Q0 | 5 |
| Q3 | 静态 FP8 FFN，其他同 Q0 | 5 |
| Q4 | Q3 + Sage FP8 attention | 5 |
| Q5 | Q4 + `qk_rmsnorm_rope_fast` | 5 |
| Q6 | Q5 + `rmsnorm_adaln_fast,gated_residual` | 5 |

Q1–Q3 使用相同的 SDPA 和精确融合，用于隔离 FFN 量化；Q4 只替换 attention；Q5/Q6 再逐项增加近似融合。
报告必须记录实际转换层数、回退次数、量化权重/缩放缓冲字节和各融合算子调用数。

### 6.4 质量只记录，不判定性能测试去留

每个配置仍保存输出并记录整帧、mask、边缘、最差帧和时序差异，精确路径另记录文件与解码 RGB 哈希。
报告不设通过/失败阈值，质量数值不影响后续性能配置的执行，也不用来删除已完成的耗时样本。

### 6.5 每个测试的统一性能记录

不增加素材、seed 或尺度测试。README 的实测与待测项合并为同一张总表，每个测试必须填写：

| 请求中位数（范围） | 纯模型推理 | 文本编码 | VAE 编码 | DiT 去噪 | VAE 解码 | 整片加速 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 5 次请求的中位数（最小–最大） | 5 次中位数 | 5 次中位数 | 5 次中位数 | 5 次中位数 | 5 次中位数 | S3 中位数 / 本项中位数 |

所有耗时单位为秒，各列直接从同一组 5 次原始记录独立计算。纯模型推理覆盖文本编码、VAE/条件编码、
latent/timestep 准备、DiT 去噪和 VAE 解码；它不是请求耗时减去某个固定开销。B0 若在 VAE 编码
OOM，则请求与加速写 `—`，VAE 编码写 `OOM` 并链接错误和资源时间线，不伪造不完整耗时。

## 7. 原始数据字段与统计口径

### 7.1 每请求必须保留的原始字段

- 身份：`run_id`、配置/案例/会话/重复编号、物理 GPU、执行顺序、完整命令和开始/结束时间。
- 时间：进程启动、模型加载、量化/编译、预热、输入扫描/解码、预处理、文本编码、条件构建、
  VAE encode、逐窗逐步 DiT、VAE decode、后处理、编码/写盘和请求 wall time。
- GPU：每卡 0.1 s 的 NVML 进程/板级显存、利用率、功耗、温度、SM/显存时钟以及可获取的 PCIe 流量；
  同时记录框架 allocated/reserved 峰值。
- CPU/I/O：进程树 RSS/PSS/USS、CPU 利用率、系统可用内存、读写字节和输入/输出文件大小；
  汇总时不得把共享页按多个进程重复计算。
- 算法计数：窗口数、有效/填充帧、DiT 步数、缓存实算/复用/探针、量化转换/回退、融合调用、
  VAE 并行历史，以及 NCCL 通信次数、字节和可测得的通信时间。
- 结果：退出码、错误阶段、输出路径/哈希、FFprobe、完整解码状态和质量记录。

所有原始采样带单调时钟，并与阶段事件对齐。缺失或后端无法提供的字段显式写 `null` 和原因，
不得以 0 代替，也不得只保留图表或汇总值。

### 7.2 汇总与不确定性

每个配置至少报告 5 次原始值、均值、中位数、标准差、MAD、最小/最大和 CV。README 主表按统一格式
展示请求中位数（最小–最大）、纯模型推理、文本编码、VAE 编码、DiT 去噪、VAE 解码和整片加速；
加载、预热、通用预/后处理与写盘在详细报告中单列。阶段、逐窗和逐步 DiT 分布均保留，不只提供整片时间。

不静默删除离群值。受到外部进程、源码变化、采样器故障或输出损坏影响的请求标为 `contaminated`，
保留原始记录并补跑等量样本；性能汇总同时给出正式样本和全部样本。质量指标始终独立展示，
不参与样本纳入、配置排序或继续执行的判断。

## 8. 执行顺序与无效运行处理

1. 先完善测量字段和数据清单；小输入只做功能自检，不记入性能结果。
2. 复现 B0 的 OOM 边界；无论成功或 OOM 都记录完整资源时间线，再审核基线描述。
3. 按 GPU 数分层，以平衡顺序运行 B1、S0–S2、M2、V0–V5、C1–C6、Q1–Q6；轮换物理卡和配置先后。
4. 正式性能会话串行执行，避免主机 I/O 争用；每项一次预热后连续完成 5 个请求。
5. 相邻配置等待 GPU 温度、时钟和空闲显存恢复到记录的空闲区间，而不是只固定等待秒数。
6. 外部 GPU 进程、源码变化、参数偏离、采样器故障或输出损坏只使受影响运行无效；保留记录并补跑，
   不取消同一配置或后续配置。
7. 若相邻配置差异很小或统计范围重叠，只标记结论不确定；不设置性能或质量门禁，亦不据此停止矩阵。
8. 配置不受支持或持续运行失败时，保存命令、异常、资源时间线和最小复现；其余配置继续执行。

## 9. 产物、完整性审计与 README 回填

每个批次写入新的结果目录，至少保留：

- `dataset_manifest.json`：固定素材、mask、prompt、seed、媒体元数据与全部哈希。
- `environment.json`：源码/工作区、依赖、模型、GPU/驱动/拓扑、系统和初始空闲状态。
- `sessions.jsonl` / `requests.jsonl` / `stages.jsonl`：会话、请求和逐阶段原始事件。
- `system_metrics.jsonl`：CPU、I/O 与逐卡 NVML 时间序列；`algorithm_counts.jsonl`：算法/通信计数。
- `outputs.jsonl` / `errors.jsonl`：输出规格、解码、哈希、质量记录、错误和污染原因。
- `summary.json`：按配置、请求和阶段汇总的原始值与统计量。
- `completeness.json`：预期/实际样本数、缺失字段、无效/补跑映射和配置解析值。
- 所有输出视频及 `source_changes_during_run.json`；图表必须可由上述原始数据重建。

每批完成后先做数据完整性审计：请求数、会话数、阶段字段、资源采样、实际解析配置、输出和错误记录
均与计划对账。该审计只确认数据是否齐全，不评价性能或质量好坏。

README 只回填已完成的正式结果，并在统一总表中为每项填写请求中位数（范围）、纯模型推理、文本编码、
VAE 编码、DiT 去噪、VAE 解码和整片加速。整片加速统一以 S3 为 1.00×；B1 → S3 的跨实现工程差异
和 S0 → S3 的同源码差异另作文字说明。候选路径的性能和质量分开列示；未完成项保持“待测”，
不用单次筛选值填入正式表。
