# 单卡 TeaCache / CacheDiT 实现检查

本轮按用户要求检查完整擦除效果，不设置 SSIM 门槛。检查当前源码，运行缓存回归，
并用同一单卡会话对比无缓存、TeaCache 和 CacheDiT 的完整输出。不导入 `sglang`。

## 实现检查

| 项目 | TeaCache | CacheDiT |
| --- | --- | --- |
| 探针 | 第一层 RMSNorm + 时间调制后的输入，含当前视频 latent 信息 | 每步实际计算前部 block，以前部输出减输入作为探针 |
| 判定 | 相邻步探针的相对 L1 累加，与阈值比较 | 与最近一次实际计算中段时的前部残差比较，不在缓存命中时移动参考点 |
| 缓存内容 | 全部 Transformer blocks 的输出减输入 | 中间 blocks 的输出减前部输出 |
| 命中执行 | 当前输入加缓存残差，继续实际计算输出 norm、调制和投影 | 实算前部，加缓存中段残差，再实算配置的后部及输出投影 |
| 残差精度 | FP32 存储和加减，恢复原激活 dtype | 同左 |
| 默认参数 | threshold=0.3，warmup=4，连续复用最多 1 步 | threshold=0.3，前 1 / 后 0 block，warmup=4，连续复用最多 1 步 |
| 末尾保护 | 最后 1 个实际 scheduler step 强制计算 | 同左 |
| 单卡逐层卸载 | 支持；缓存命中只为探针执行首层驻留计划 | 显式拒绝，需要关闭 DiT 逐层卸载 |

两者默认均关闭；文本投影缓存为独立选项，auto 在残差缓存开启时也会开启。
本轮完整视频对照显式关闭文本缓存，隔离残差缓存效果。`linear` 残差预测器默认关闭，
仅使用两次真实计算学习变化率，按 step 序号外推，最多外推一个观测间隔；不等同于擦除质量保护。

已核查以下边界：

- 单卡每个实际 timestep 分别调用负、正 CFG 分支，二者各自持有探针和残差；scheduler 仍逐步执行。
- 每个窗口新建缓存上下文，窗口结束或异常退出时释放残差、预测器和文本缓存，不跨窗口复用。
- 实际 timestep 数来自 `len(timesteps)`，不会把配置 50 步误当作 strength 截取后的 40 步。
- 首步、预热、末步、连续复用上限、形状变化、步序不连续和非有限判定值有强制计算保护。
- 强制实算模式可与无缓存模型严格对照；TeaCache 探针通过模块调用触发卸载 hooks。

入口为 `pipelines/stages/eraserdit_erase/denoising.py`，分段执行在 `cache/eraserdit.py`，
控制器在 `cache/teacache.py` / `cache/cache_dit.py`，模型专用 FP32 残差在
`cache/eraserdit_prediction.py`。未发现本轮回归能够复现的分支串用、跨窗残留或伪缓存问题。

## 对完整擦除的限制

1. **判定没有擦除区域保护。** `cache/consensus.py:relative_l1` 对全部 token/channel
   求和；没有 mask 内、mask 边缘或逐帧最大变化指标。小目标或短暂快速运动的变化可能被
   背景及时域平均稀释。探针虽然间接包含 mask 条件，判定权重并没有专门关注 mask。
   `results/single_gpu_cache_audit_20260929/probe_blind_spot.py` 给出受控示例：
   1% token 的探针变化 100%，全局相对 L1 仅 0.01，两种缓存仍可命中。
   这是判定能力的边界，不等于真实视频已经发生擦除失败。
2. **TeaCache 没有本模型拟合系数。** `select_eraserdit_coefficients` 使用 `(1, 0)`
   恒等多项式，即直接累计探针相对 L1。0.3 是启发式阈值，不是“30% 擦除误差”或质量保证。
3. **CacheDiT 默认没有后部 Transformer block 实算。** 默认 1/0 的命中步只实算第一个
   block，其余中段复用。可评估 1/1 或 1/2，以额外计算换取条件更新机会；不能仅凭结构
   推断必然消除残留。末尾仅保护一步也不能保证修复此前轨迹偏移。
4. **命中率与完整擦除没有直接等价关系。** 不能因 SSIM、命中率或输出解码正常而判定
   擦除成功；需要查看人物轮廓、肢体、残影、边缘接缝和时间连续性。

### 当前源码的单卡实测

| 模式 | 完整请求（不含加载） | 去噪 | 复用分支步 | 缓存持有张量峰值 |
| --- | ---: | ---: | ---: | ---: |
| 无缓存 | 246.282 s | 217.439 s | 0 / 160 | — |
| TeaCache | 146.685 s | 119.898 s | 72 / 160（45%） | 765 MiB |
| CacheDiT | 150.558 s | 123.286 s | 72 / 160（45%） | 1020 MiB |

相对本次无缓存请求，TeaCache 耗时减少 40.44%，CacheDiT 减少 38.87%。
三项均只跑一次，且无缓存为会话首个请求，不能解释成稳定排名；模型加载不计入请求。
整请求 peak allocated 均约 34.029 GiB，缓存持有张量不是整模型峰值，不能直接相加。

**本片的 0.3 阈值没有触发过重算。** TeaCache 实际评估的探针距离为 0.00822–0.08164，
CacheDiT 为 0.01138–0.09666。两项均由预热强制计算 16 个分支步、连续复用上限强制计算
68 个分支步、末步保护强制计算 4 个分支步，共 88 次计算、72 次复用。
在本片上，当前参数主要形成预热之后交替计算/复用的节奏；继续提高阈值不会提高命中率。
这不是说明两个探针没有作用，而是本片的阈值没有成为约束条件。

## 后续优先级

- 以完整擦除为目标，先增加 mask 内和边缘区域的局部变化保护，并考虑逐帧最大变化，
  再决定是否允许全局探针命中的步骤复用；避免小目标和短时运动被全片平均稀释。
- 当前样片已经达到连续复用 1 步的命中率上限，单纯提高阈值没有收益。
  若继续提速，应独立比较连续复用 2/3 步，同时检查完整擦除；本轮未验证这些更激进参数。
- CacheDiT 可比较后部实算 1/2 个 block、末尾保护 2/3 步的收益与代价，不能先验宣称比
  TeaCache 擦得更干净。当前结果尚不支持为全部素材自动选择某一种缓存。

本轮新增检查报告与本地实验产物，未修改缓存算法或默认参数。
