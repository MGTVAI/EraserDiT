# FP8 性能优化（2026-10-04）

后续完整素材验收：静态 FP8 FFN + Sage FP8 + 快速融合组合未通过两素材质量门槛，
不作为通用推荐预设；下文保留 121 帧实验范围的结果。见 [最新验收记录](l40s_validation_20261004.md)。

本轮以速度优先，允许量化输出发生数值变化；以完整视频的耗时和质量记录评价候选。

## 使用

```sh
--transformer-quantization fp8_w8a8_static --quantization-scope ffn
```

新增实验模式 `fp8_w8a8_static`：权重按整张量动态量化一次，激活固定 scale=1/8，
采用 E4M3、快速累加和 BF16 GEMM 输出。每次激活只执行一个转换 kernel，省掉全张量
absmax 和 scale 归约。可表示的激活范围为 ±56，超出范围会饱和；这不是自动校准模式。
默认仍为未量化 BF16；已有动态 FP8 模式保留，CLI 和服务端均支持新模式。

三种 FP8 模式的 `ffn` / `blocks` 范围均自动融合 GELU 与降维层的激活量化。
仅匹配 tanh GELU 和中间的恒等操作，`ffn_up` 不移动 GELU。每层独立的 128 KiB 查表
buffer 支持卸载；28 层共 3.5 MiB。静态模式仍使用查表 GELU，因为近似 tanh 试验没有更快。

修复局部编译路径：PyTorch 2.6 无法正确分析 FP8 内联汇编的输入修改关系，直接编译量化
kernel 曾出现非有限输出。量化现使用无输入修改的自定义算子边界和 fake 实现；普通推理
直接调用 kernel，保持正常调用开销。CPU 转换、逐层卸载与局部编译组合已通过 GPU 检查。

## 算子和 DiT

L40S、PyTorch 2.6.0+cu126；block 0 真实权重、固定 seed 合成 BF16 激活。
完整 FFN 包括两个 Linear、GELU、激活量化与 bias；5 组 × 20 次，预热后交替顺序，
CUDA events。单位 ms：

| token 数 | BF16 eager | 旧动态 FP8 eager | 静态 FP8＋融合 eager | BF16 Graph | 旧动态 FP8 Graph | 静态 FP8＋融合 Graph |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1,200 | 0.411 | 0.676 | 0.398 | 0.446 | 0.336 | 0.284 |
| 32,640 | 11.695 | 9.673 | 6.988 | 12.187 | 9.699 | 6.940 |

大 FFN 相对旧动态 FP8 减少 **27.76%**，相对 BF16 为 **1.67×**。
相对 BF16 的合成 FFN relative RMSE：动态 FP8 约 2.23%，静态快速累加约 4.78%。
Graph 只用于算子诊断，视频入口未启用 Graph。这些算子误差不是视频质量指标。

真实权重、完整 DiT 合成输入，32,640 token，Sage FP8 per_thread Attention，三组交替顺序：

| 配置 | forward 中位数 s | 对 BF16 输出的 relative RMSE |
| --- | ---: | ---: |
| 旧动态 FP8 FFN | 2.0365 | 0.01664 |
| 动态 FP8＋GELU 融合 | 1.9933 | 0.01664 |
| 固定激活 scale＋GELU 融合，普通累加 | 1.9702 | 0.01662 |
| 固定激活 scale＋GELU 融合，快速累加 | 1.9587 | 0.02107 |

最终候选减少约 **3.82%**。该次合成输入的 56 层激活检查中最大绝对值为 53.25，
未观察到 ±56 饱和；这不能代表其他视频或全部去噪步。

另筛选了融合 FP8 GEMM、四元素打包转换和八组量化分块。降维融合 GEMM 比原生更慢，
打包转换及分块没有带来足够收益，均未进入生产实现。原始结果保留于本机实验目录。

## 视频协议

同一 L40S GPU 2 串行运行旧动态 FP8 和静态 FP8 候选，各两次。固定 121 帧、1920×1080
视频与 mask、seed=42、CFG=3、50 步配置、strength=0.8（实际 40 去噪步）。
使用 SDPA，关闭缓存和手工融合，DiT 常驻、T5/VAE 卸载；首任务预热 2 步。
请求耗时排除模型加载和预热。旧路径使用冻结源码；静态候选在预热中每层只检查一次激活范围，
检查 hook 随即移除，不计入请求计时。质量始终以原始 BF16 SDPA 视频为参照。

## 视频性能

| 配置 | 去噪 s | 纯推理 s | 请求 s |
| --- | ---: | ---: | ---: |
| 旧动态 FP8，第一次 | 214.552 | 228.921 | 248.279 |
| 旧动态 FP8，第二次 | 214.880 | 229.320 | 247.808 |
| 静态 FP8，第一次 | 208.044 | 222.458 | 240.491 |
| 静态 FP8，第二次 | 209.001 | 224.361 | 242.633 |
| 旧动态中位数 | 214.716 | 229.121 | 248.044 |
| 静态中位数 | 208.522 | 223.409 | 241.562 |

去噪减少 **2.88%**，纯推理减少 **2.49%**，请求减少 **2.61%**（6.481 s）。
这是一段素材各两次的结果，不把 FFN 约 28% 的收益当作视频收益。
质量分析在第二次 GPU 去噪期间于 CPU 上运行，任务外耗时仍有波动。

峰值 allocated 从 23.5651 增至 23.5686 GiB（约增加 3.53 MiB），reserved 从
43.2305 增至 43.2344 GiB。56 个 FP8 Linear 均执行，28 层融合 GELU 累计调用
2352/4592 次（含首任务预热）。两次静态视频 SHA256 相同：
`ec42de3c404d7d6d3ecae26b01243abdcca178ee0a6f993490f7917ac25ac2d4`。

真实视频首轮预热的 56 层范围检查中，最大绝对值为 **110**，约 93.59 亿个激活元素中
有 **34 个**超出 ±56，因此静态模式确实会裁剪激活。该检查仅覆盖各层首次预热调用，
不代表全部去噪步；完整视频质量如下。

已查看首、中、末帧对照和 mask SSIM 最低的第 102 帧裁剪，未见明显新增整体失真，
